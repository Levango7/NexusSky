# WS 扇出双稳态判别实验终报（2026-11-11，注入进程数轴收官）

## 结论（先给）

- #283 扇出拆分后的代码、hz25 × 254 架 × 10 WS 客户端、注入 2/4 进程、干净环境：**7/7 干净轮零丢包零 kernel drop，全 B 型**；A 型饱和吸引子未复现。
- 实验期间全部损失样本（3/10 轮）均落在 CPU 风暴轮，kd 随**轨迹峰值**单调（80.2%→816；87.5%→3816；100% 持续→17226＋扇出 drop 85279）；p 轴无效应。冷/暖轴早前 10 轮已否。
- 终判：当前代码、已测负载面内**不存在双稳态触发点**。历史 baseline 的 A 型只可能来自 (a) #283 前代码、(b) 更高负载轴（未测）、(c) 当时的环境风暴（无轨迹纪律，不可回溯排除）。

1. 假设「冷 JIT / 暖热身」：5 cold × 5 warm（injectProcs=1）全 10 轮 B 型零丢包，冷/暖中位数无差 ⇒ 否。

## 方法（每轮）

- fresh 后端进程 + 60s 测量；硬对账 sentFrames == decoded + kernelDropEstimate，不闭合即 FAIL（10/10 闭合）。
- 轮前门：连续 3 采样 ≤25%＋pitest 不在场；每轮 CPU 轨迹落盘事后打污染标（形态学：持续 90%+＝风暴，孤立尖刺＝设计内负载）。
- 产物：`docs/capacity/20261111-12xxxx-*.json`；轨迹 `/f/tmp/capacity/cpu-coldN-pM-*.log`。

## 边界与诚实声明

- 门控盲点：`storm_check` 只查 pitest java 进程，对多 Qoder 会话的 CPU 占用不可见；间歇风暴可钻「开火前 3 采样」假静。污染只能事后按轨迹形态标，本报已标。
- 历史 baseline 15 轮（#283 前）无轨迹纪律，其饱和轮是否同样环境所致**不可回溯排除**；故「#283 消除了吸引子」只能限定为「干净环境下未复现」。
- 环境占用漂移：R1 轨迹 mean 21-30% → R5 37-48%（他会话渐忙）。干净轮零丢包结论不受影响；但 p95 尾延迟从 10ms 漂到 185ms，**跨轮比延迟必须带环境注记**。
- 深 excursion（qPk 1261/1648）零损失两轮说明队列弹性充足， excursion ≠ 饱和。
