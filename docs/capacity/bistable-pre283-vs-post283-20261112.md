## 结论（先给）

- **对照有效**：两臂同夜同环境、同门控（开火前连续 3 采样 ≤25%＋pitest 不在场）、同协议（d254/hz25/c10/60s、p2/p4 交替、全 cold）、同硬对账（sentFrames == decoded + kernelDropEstimate，两臂各 10/10 闭合），唯一变量＝代码版本（pre283 = `31afbc10` = #283^；post283 = `4bc7e93e` = #283）。
- **pre283 未复现历史 A 型饱和**：10 轮无 kd 上万 / 扇出 drop 8 万级轮次，无持续 ≥90% CPU 轨迹。历史上 15 轮 baseline（#283 前代码、旧门控口径、无轨迹纪律）的 A 型**不能由代码版本单独复现**。
- **弱信号**：pre283 有 2/10 轮带损失签名且**非风暴形态**（R1p2 kern=894＋首轮启动重叠候选；R2p4 扇出 drop=1668＋队列峰值 4075/4096 近满、无 kernel drop）；post283 干净轮 0/7 损失。方向与「#283 前扇出更重」一致，但 n=10/7、Fisher 单侧 p≈0.33，**不立因果**。
- **合并判读**：A 型饱和＝CPU 竞争 / 环境风暴签名（两臂的损失都落在轨迹高峰、首轮启动重叠或队列近满处）；「#283 消除吸引子」仍只能限定为「干净环境下未复现」——本轮对照既未证实也未推翻该因果表述。

## 差异分析

- **干净轮子集**（post 7 轮 / pre 8 轮，零损失）：qPk 中位数 86 vs 90.5（post283 深 excursion 1261/1648 零损失；pre283 干净轮最高仅 139）；p95 中位数 37 vs 11；p99 中位数 218 vs 55。post283 干净轮的延迟尾更高，但两臂非严格同时（相隔约 12h，环境占用同带 21–48% 漂移），跨臂比延迟只作注记不作结论。
- **损失轮逐一归因**：
  - pre R1p2（kern=894）：首轮、backendStartSec=9、轨迹仅单尖刺 59.3%。post283 R1 同为首轮但有 kd=0。kernel drop 出现在观测 CPU 仅 59.3% 处，不落在 post283 臂的「kd 随轨迹峰值单调」曲线上（该曲线 peak 80.2→kd 816）。解释候选：采样混叠（5s×12 样本可漏掉突刺）/ 首轮启动重叠 / pre283 特异弱项，n=1 不可区分。
  - pre R2p4（fan=1668、qPk=4075、kern=0）：队列打满 99.5% 但摄入路径零损失、扇出路径丢 1668。这是两臂中唯一「队列近满＋真实丢失」的非风暴轮，最接近弱化版 A 型签名；但轨迹无 ≥90% 持续段（max 71.1、形态散刺），不能排除微突刺混叠。
- **统计**：非风暴轮损失率 pre 2/10 vs post 0/7，Fisher 单侧 p≈0.33，不显著。

## 边界与诚实声明

- 采样器 5s×12 有混叠盲区；门控对他 Qoder 会话 CPU 占用不可见（两臂同盲，非本轮新引入）。
- 两臂非交错（post283 先跑、pre283 后跑约 12h），环境占用有漂移；损失判定依赖轨迹形态学，形态学本身是事后判据。
- 首轮启动重叠未做控制变量（两臂 R1 都在该注记下，pre R1p2 的损失不能从启动效应中剥离）。
- 本轮对照只覆盖 hz25/d254/c10/ip2-4/60s 负载面；更高负载轴未测。
