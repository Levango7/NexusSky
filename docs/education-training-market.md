## 2. 买家画像与采购逻辑

### 2.1 买家类型（按采购频次排序）

1. **职业技术学院（主力）**——「无人机应用技术」「低空经济」新专业建设，实训室是专业申报的硬条件。
2. **本科院校/学院**——新建低空经济相关专业、研究中心、测试实验室。
3. **行业院校**（司法警官、航空类）——行业特色实训（如「未来网络低空经济实训基地」）。
4. **培训机构 / 产教融合基地**——政府补贴项目配套。

### 2.2 采购动机（四个驱动力）

- **专业申报/评估验收**：教育部专业目录带动，「没有实训室 = 不能开专业」。
- **招生展示**：编队表演、数字孪生这类「看得见」的演示是招生与验收的刚需素材。
- **技能大赛**：全国职业院校技能大赛无人机赛项——实训室需能对接赛项训练。
- **地方政策资金**：低空经济写入地方规划，配套职教/产教资金。

### 2.3 采购形态

- **公开招标 / 竞争性磋商**（门槛以下可磋商，流程更短——荆楚理工用的就是竞争性磋商）。
- **软硬件打包**为「实训室整体建设」——软件**很少单独立标**。
- ⇒ **现实约束**：软件必须随集成商的整包进场；或由有资质的集成商代投。

## 3. 实训室典型需求清单（能力域 × 优先级）

> 基于行业公开资料与实训室建设惯例整理（**行业估计**，待更多招标文件样本校准）。

| 能力域 | 说明 | 优先级 |
|---|---|---|
| 飞行模拟 / 仿真训练 | 多机仿真、故障注入、天气、SITL——室内教学主力 | ★★★ |
| 地面站系统 | 任务规划、实时监控、航线执行——核心技能 | ★★★ |
| 编队表演 / 集群演示 | 队形编排、动作同步、灯光——展示型刚需 | ★★★ |
| 教学管理 | 班级 / 学号 / 任务下发 / 成绩记录 | ★★★（多由校方或第三方承担） |
| 数字孪生 / 场景回放 | 状态镜像、轨迹预测、时间轴回放——可视化教学 | ★★ |
| 链路 / 组网仿真 | 信号损伤、mesh 自组网——通信原理教学 | ★★ |
| 低空监管概念演示 | UOM / 实名登记 / 电子围栏——合规教学内容 | ★★ |
| 二次开发实训 | SDK / API 开发、课程设计——面向本科与研发方向 | ★★ |

## 4. NexusSky 现有能力映射

> 对照仓库现状（2026-11-09 调研时点；入库时计数口径：5962 单测全绿）。

| 实训需求 | NexusSky 对应能力 | 现状 | 差距 |
|---|---|---|---|
| 飞行模拟 / 仿真训练 | `drone-sim`（多机 / 天气 / 故障注入 / 载荷 / 视觉感知） | **强**（1477 单测，PoC 成熟） | 缺教学友好的预设场景包 |
| 地面站 | `gcs-web`（38 功能面板、实时监控、任务管理） | 可用 | 缺教师视图 |
| 多机协同调度 | `cloud-backend` 调度引擎（任务分配 / 冲突避免 / 重分配） | 可用 | — |
| 编队表演 | 编队模块（几何队形 / 动作同步 / 灯光控制） | 可用 | 编排 UI 易用性待打磨 |
| 数字孪生 | 孪生模块（状态镜像 / 轨迹预测 / 场景回放 / 虚实对比） | 可用 | — |
| 链路仿真 | `link-sim`（Gilbert-Elliot 损伤 / mesh 中继 / 多地形） | 可用 | — |
| 监管演示 | `regulator-sim`（Mock UOM 状态机 + 上报链路） | 可用（教学用途） | 需口径说明（教学模拟 ≠ 真实监管） |
| 二次开发实训 | `sdk-java` / `sdk-python` + OpenAPI 3.0 | 可用 | 缺实验手册 |
| 教学管理 | — | **缺** | 轻量补（班级/评分）或对接校方平台 |
| 一键部署 | Docker / docker-compose / Helm | 对教师过重 | **缺教学版安装器** |
| 教学素材 | — | **缺** | 课件 / 实验指导书 / 案例库 |

**结论**：能力栈覆盖实训需求 **8/9 个能力域**（教学管理为外购/自建项），产品化差距集中在「**教学化封装**」——安装器、教师界面、教学素材、班级管理。

## 5. 需要补什么（产品化差距清单）

### P0（切入必须，2–4 周）

1. **教学版一键安装包**：docker-compose 单机起（教学机房场景），安装文档面向**非技术人员**（教师）。
2. **实训场景预设包 ×10**：编队表演 / 应急测绘 / 物流调度 / 链路损伤 / 多机冲突避免……每个 = 一键加载的任务脚本 + 讲解文档。
3. **五分钟演示流**：编队表演 + 数字孪生的展示脚本（招生 / 验收 / 汇报用）。

### P1（竞争力，1–2 月）

4. **教师控制台 MVP**：班级 → 学生 → 任务下发 → 成绩回收（轻量实现，可复用现有租户机制）。
5. **实验指导书 ×10**：MAVLink 协议解析 → 地面站 → 多机调度 → 编队 → 数字孪生，阶梯式。
6. **技能大赛场景包**：对接全国职业院校技能大赛无人机赛项训练方向。

### P2（规模化，3–6 月）

7. 教学视频 / 微课素材；8. 课程 PPT 模板与考核题库。

## 6. 商业模式建议

### 6.1 新增「教育版」授权（独立于现有三档）

| 项 | 内容 |
|---|---|
| 授权形态 | **实训室授权**（单套 = 一间实训室，不限席位）+ 部署服务 + 素材包 + 年维护 |
| 定价锚点（**估计**） | 软件 8–25 万/套 + 年维护 15%；整包（硬件主导）通常 50–300 万，软件占比合理 |
| 与现有三档关系 | 并列新增，不替代 基础版 / 应急版 / 完整版（后者面向厂商/集成商的 SDK 授权） |

### 6.2 渠道策略（结合「个人开发者、无公司主体」的现实约束）

1. **集成商分包（首选）**：找**教学仪器/教育装备集成商**，我方供软件 + 技术方案，借其资质投标——**不需要自己投标**。
2. **产教融合共建**：与院校共建「联合实验室」，低成本换取案例与背书。
3. **区域代理**：产品成型后找教育行业代理商铺渠道。
4. **校方直采**：需企业主体 + 类似业绩——**中后期**（主体问题见 6.3）。

### 6.3 主体问题（如实标注）

- 院校采购**必须企业主体**（营业执照 + 对公账户 + 通常要求类似业绩）。
- 个人身份的路径：**注册个体户/小微**（线上办理、成本低）或**先走集成商分包**（无需自己投标）。
- 该决策属用户个人事务，本文只标注约束与两条路径，不做推荐。

## 8. 风险与边界

- **不做硬件**：教学无人机 / 工作站 / 网络设备由集成商或厂商提供，软件聚焦。
- **不承诺**：就业率、赛事成绩等敏感承诺一律不写进标书。
- **口径诚实**：`regulator-sim` 是**教学模拟**（非真实监管对接）；真机飞行部分需客户自备设备与空域，教学版以仿真为主。
- **知识产权**：全栈独立实现（与 DJI 无代码依赖；DJI 对接为可选集成项，另见 `protocol-vendor-integration.md`）。
- **调研修正**：本分析基于 2026-11-09 单窗口样本，更多关键词扫描完成后将校准数字与结论（见 §1 边界声明）。

## 附：与「政企运营平台」路线的关系

本文档只论证**教育赛道**为「当前可见现金流最近的切入市场」，**不否定**应急 / 电力 / 安防等运营平台路线——后者买家（应急管理局、电网、公安）预算更大但要求企业资质、真机验证与交付业绩，适合作为**第二阶段**目标。两条路线共用同一套技术底座（本仓库），差异在**产品化封装与渠道**，不冲突。
