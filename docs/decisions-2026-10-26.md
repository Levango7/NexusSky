## 决策一：C5 第④步「动 prod」——**保持出厂关闭**（ROADMAP:355 的 ⬜ 就此落账）

**结论**：`mavlink.signing.enabled` 在 prod profile **保持 `false`**，
`MavlinkSigningConfigurationTest.prodProfileStaysDisabled` 这条测试**不改**。

**理由**：

1. 本系统**尚无 prod 机队**。strict 的唯一风险面是「未配密钥的设备整链失联」，
   而当前不存在任何一台会因此失联的真机——收益为 0，风险模型却要开始运转。
2. 打开是一次**硬切换**（签名块无 key id，没有宽限期），切换前必须完成的
   「逐机发放配置单 + 面板/告警先接好 + 回滚演练」三件事全部依赖真实机队与真实运营流程，
   现在做了也无法被真实验证。
3. 验签能力 fail-closed 且被 CI 持续验证（`UdpGatewaySigningTest` 8 例 + 变异测试），
   staging strict 已在跑——**能力就绪与行为变更可以解耦**，解耦正是这三步走设计的意义。

**重开条件**（全部满足才允许动，操作手册见 `docs/signing-prod-rollout.md`）：

1. 存在 prod 机队，且**每一台**在网设备完成密钥发放并出现在
   `GET /api/v1/mavlink/signing/provisioning` 的发放配置单上（`VERIFIED` 态）；
2. prod 先以 permissive（`enabled=true` + `reject-unsigned=false`）运行 ≥7 天，
   `aerofleet_signing_rejected_total{reason=...}` 看板与告警静默期已配置
   （注意：permissive 阶段的 `unsigned` 计数才是「有机没配密钥」的证据，strict 下恒 0）；
3. 回滚路径演练过一次：关闭开关 → 设备恢复通信（staging 演练即可）；
4. 维护窗口约定：切换与首日观察在同一个人工值守时段内完成。

**谁改谁负责**：真要翻 prod 的人必须同笔改动 `prodProfileStaysDisabled` 测试并在本文件追加决策条目——
这正是该测试存在的原因（改动会被 CI 拦下，逼出一次显式决策）。

## 决策二：GB 46750（2026-11-01 硬 deadline）——**技术前置已满足，真实 UOM 联调立项为下一个外部依赖主线**

**结论**：不为凑 deadline 做假动作。C2 的技术实现（OPEN_DRONE_ID_* 12900–12915 广播链路、
e2e-rid.ps1、UOM 上报形状层）已按模拟器口径闭环；deadline 的**真实口径**（「不具备运行识别
功能不应运行」针对**运行中的真实航空器**）只对真机飞行有效——本系统当前没有真机在飞，
因此 deadline 本身不构成本仓的合规违约事件，**不启动任何为赶日期而跳过真实验证的动作**。

**真实 UOM 联调就绪清单**（把「模拟器对端」推进到「真对端」前必须逐项落定，按可立即推进排序）：

| # | 事项 | 现状 | 前置 |
|---|---|---|---|
| 1 | 确定 UOM 对接主体与接口环境（监管方提供测试环境地址/账号，或经由运营人资质申请） | 无 | **外部**：需要一个真实运营主体；个人/无资质主体拿不到 UOM 测试环境 |
| 2 | `UomReportSink` 真实现适配器（当前 `sink-type` 缺省 Noop；SPI 门禁已把「未验」记成可见的账） | 接口形状已定（C1，23 文件） | #1 |
| 3 | `regulator-sim` 与真 UOM 的**协议差异比对**（6 端点请求/响应逐字段对照真实 API 文档） | regulator-sim 可注入故障，可作差异回放器 | #1 给出 API 文档 |
| 4 | RID 广播真实报文抓取比对（GB 46750 报文字段 vs OPEN_DRONE_ID_* 编码，e2e-rid.ps1 断言扩展） | 编码与官方 msgId 对齐 | 真机或符合标准的广播模块 |
| 5 | 联调通过后把 C1/C2 条目的「对端为模拟器」边界声明改为真对端口径 | ROADMAP:359 | #1–#4 |

**本仓侧可先行、不依赖外部的**：#3 的差异比对框架可先搭（拿公开的 UOM 接口规范逐字段建表），
#2 的真实现可按接口规范先写骨架 + 合同测试（SPI 门禁会把它从「未验」账里顶出来）。
建议把 #1（找对接主体）作为**用户侧行动项**推进，仓内工作与之并行。
