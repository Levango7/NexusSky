# NexusSky · 产品定位白皮书

> **文档版本**：v1.0  |  **日期**：2026-09-19  |  **阶段**：PoC → 中间件化定位转换

> **产品代号**：NexusSky（天枢）—— 多机协同调度云平台中间件

---

## 0. 为什么写这份文档

NexusSky 起步时定位为"无人机智能飞控系统"，PoC 阶段以软件模拟器代替真飞控、
在同一架构上跑通了 MAVLink 协议栈、任务上传、轨迹跟踪、链路损伤回归与
应急编排全链路。**继续以"飞控系统"对外定位存在三个错位**：

1. 飞控市场已被 PX4 / ArduPilot / 大疆占据，自研飞控对客户无吸引力；
2. PoC 阶段没有真机气动模型，对外宣称"飞控"会被一眼看穿；
3. 项目实际沉淀的能力——**多机协同调度、mesh 自愈组网、应急指挥编排、
   多厂商协议兼容**——其价值远高于"再写一个飞控"。

**重新定位**：NexusSky 是面向二线整机厂商、行业解决方案商、飞控厂商与
eVTOL 企业的**多机协同调度云平台中间件**。客户自带飞机（无论 PX4 / ArduPilot /
自研飞控 / 大疆），NexusSky 提供从机队注册、任务编排、链路组网到应急指挥的
**中间层能力**，不与客户在飞控或整机制造层竞争。

## 1. 产品定位

### 1.1 一句话定位

> **NexusSky 是兼容多厂商飞控协议的多机协同调度云平台中间件，把"几架飞机"
> 组织成"一支可指挥、可组网、可应急的机队"。**

### 1.2 定位三要素

| 维度 | 是 | 不是 |
|---|---|---|
| 层级 | 中间件（介于飞控与行业应用之间） | 飞控、整机、行业 SaaS 应用 |
| 卖点 | 多机协同 + 应急指挥闭环 | 单机性能、气动算法、飞控芯片 |
| 部署 | 私有化为主，模块化单体可裁剪 | 公有云 SaaS 强绑定 |

### 1.3 价值主张（对四类客户分别成立）

- **二线整机厂商**：你们造飞机，NexusSky 让你的飞机开箱即有云调度能力，
  不必从零写后端。
- **行业解决方案商**：你们懂应急/巡检/农业场景，NexusSky 提供应急指挥
  闭环与安防联动底座，你专注上层业务。
- **飞控厂商**：你的飞控强，但缺云平台与多机调度，NexusSky 以 MAVLink
  中立协议对接，补齐你的上层短板。
- **eVTOL 企业**：适航与运营期多机调度是刚需，NexusSky 提供数字孪生与
  多层级中继调度能力，降低验证与运营成本。

### 1.4 阶段诚实声明

当前为 **PoC 阶段**：以 `drone-sim` 软件模拟器代替真飞控，协议、接口与
真实 PX4 硬件一致，但**未在真机集群上完成验证**。本白皮书所列能力均已
在模拟器与 e2e 回归脚本中跑通（详见 §2 每项的"实现状态"），但商用落地
需要补齐鉴权、持久化与真机集成（详见 §7）。

## 2. 核心能力清单

> 以下能力均对应 README.md 中已实现的里程碑（M0a–M9、4a），每项标注
> **实现状态**与**边界**，不夸大。

### 2.1 Mesh 组网（AODV-lite 路由）— M5

- **能力**：AODV-lite 多跳动态路由（`MeshRouter` / `RouteTable` /
  `NeighborTable` / `RreqCache`），支持路由发现、自愈重构、链路质量评估。
- **协议**：MAVLink 消息 450–454（MeshHeartbeat / RouteRequest /
  RouteReply / RouteError / NeighborTable）。
- **接口**：REST `/api/v1/mesh/*`，前端 `MeshTopologyPanel.jsx` 拓扑可视化。
- **实现状态**：模拟器 + link-sim 多跳中继下 e2e 通过；RERR 处理遵循
  RFC 3561 §6.5 语义（`findAffectedTargets` → `removeByNextHop`）。
- **边界**：未在真实多架次无线环境下验证；路由表为内存态，重启即丢。

### 2.2 移动基站 + 卫星中继（多层级通信）— M6 + M7

- **能力**：
  - M6 无人机搭载 LTE / WiFi / LoRa 基站载荷（`CellTowerFactory` /
    `CoverageArea` / `HandoverManager`），支持覆盖区计算、终端接入、越区切换。
  - M7 LEO 卫星 + HAPS 高空平台 + Mesh 三层级中继
    （`HierarchicalRouter` / `LeoConstellation` / `HapsRelayNode`），
    支持卫星过境窗口预测、层级路由决策、链路切换。
- **协议**：MAVLink 消息 455–458（基站）、459–461（星地中继）。
- **接口**：REST `/api/v1/celltowers/*`、`/api/v1/satlink/*`。
- **实现状态**：模型与算法已实现，e2e 在 link-sim 损伤链路下跑通；
  Starlink 画像（25s 通 / 2.5s 黑洞，9.6% 丢包）下完整任务流 PASS。
- **边界**：未对接真实卫星过境数据源；基站载荷为软件模型，未在真实
  通信载荷硬件上验证。

### 2.3 地形适配（RF 信号建模）— M8

- **能力**：山地 / 森林 / 沼泽 / 城市等地形分类与 RF 衰减建模
  （`TerrainGrid` / `TerrainClassifier` / `EnhancedRadioEnvironment` /
  `FlightConstraintChecker`），支持地形变化监测、飞行约束检查、
  覆盖范围地形衰减。
- **协议**：MAVLink 消息 462–464（TerrainTypeMap / TerrainUpdate /
  FlightRestriction）。
- **接口**：REST `/api/v1/terrain/*`，前端 `TerrainMapPanel.jsx`。
- **实现状态**：地形分类与 RF 衰减模型已实现，e2e 在 `--terrain hill:...`
  场景下验证撞地保护与围栏越界。
- **边界**：RF 衰减为经验模型，未与实测传播数据校准；地形网格分辨率
  受限于模拟器配置。

### 2.4 空地一体化应急指挥（ONVIF 安防接入 + 报警联动 + 应急工作流）— 4a

- **能力**：
  - **ONVIF 安防设备接入**（`surveillance` 包）：兼容**海康威视 / 大华 / 宇视**
    三大安防硬件供应商协议，支持设备发现、RTSP 视频流拉取、PTZ 云台控制、
    事件订阅。
  - **报警联动编排引擎**（`alarm` 包）：报警事件 → 联动规则匹配 → 自动触发
    无人机侦察任务（起飞 → 飞往报警位置 → 盘旋侦察 → 实时回传 → 返航）。
  - **应急指挥工作流**：六阶段（接报 → 研判 → 部署 → 执行 → 评估 → 总结），
    一键应急响应自动走完全流程。
  - **GCS 视频融合面板**：`SurveillancePanel`（设备列表 / 多画面分屏 / PTZ）+
    `AlarmPanel`（SSE 实时报警 / 联动规则管理 / 一键应急）。
- **协议**：MAVLink 消息 477–479（AlarmTrigger / AlarmAck / SurveillanceStatus）。
- **实现状态**：协议层与编排引擎已实现，前端面板已接入；ONVIF 协议兼容性
  在三大厂商设备上未做现场联调。
- **边界**：报警联动规则为内存态配置，未持久化；视频流为 RTSP 透传，
  未做转码与分发优化。

### 2.5 应急任务编排（全流程闭环）— M9

- **能力**：将 M5–M8 能力编排为完整应急响应工作流：
  **灾区测绘 → 覆盖规划 → 组网部署 → 持续服务 → 自愈重构**。
  - `OrchestrationEngine` 五阶段状态机；
  - `CoverageOptimizer` 贪心 + 局部优化部署方案；
  - `DynamicReconfigurator` 处理无人机损毁 / 电量不足；
  - `PriorityScheduler` 四级抢占式调度（搜救 > 指挥 > 测绘 > 常规）；
  - `ScenarioPresetFactory` 支持地震 / 泥石流 / 火灾一键启动。
- **协议**：MAVLink 消息 465–467（EmergencyMissionPlan /
  CoverageOptimization / EmergencyPriority）。
- **接口**：REST `/api/v1/emergency/*`，前端 `EmergencyOrchPanel.jsx`。
- **实现状态**：编排引擎与场景预设已实现，e2e 在模拟器多机场景下跑通
  五阶段流转。
- **边界**：调度算法为启发式，未与真实应急指挥 SOP 对齐验证；场景预设
  参数需按实际灾种调优。

### 2.6 布控球自动发现 + 一键注册

- **能力**：基于 ONVIF 设备发现协议，自动扫描局域网内布控球 / 安防设备，
  识别厂商（海康 / 大华 / 宇视）、型号、能力集，一键注册到
  `SurveillancePanel` 设备列表。
- **实现状态**：ONVIF 发现协议已实现，厂商识别规则已内置；未在大型
  跨网段安防网络下验证发现规模。
- **边界**：发现范围限于同网段（ONVIF WS-Discovery 多播），跨网段需
  手动指定 IP 段。

### 2.7 无人机遗失辅助查找

- **能力**：基于飞行日志持久化（`flight-logs/flight-YYYY-MM-DD.jsonl`，
  遥测 1Hz 节流、告警 / 任务 / 上下线即时落盘）+ 轨迹重建接口
  （`GET /api/v1/flightlog/track?sysid=1`），为遗失无人机提供最后已知
  位置、轨迹回放与失联时刻上下文。
- **实现状态**：日志落盘与轨迹重建已实现，单测覆盖往返 / 节流 / 过滤 /
  轨迹重构 / NaN 容忍（7 个单测）。
- **边界**：日志为本地 JSONL 文件，未做分布式存储；遗失查找依赖失联前
  日志已落盘，失联后无主动追踪能力（无 4G 回传 / 无信标）。

### 2.8 丐版三档硬件方案（toy / standard / advanced）

> 详见 [`docs/budget-hardware-design.md`](budget-hardware-design.md)，
> 此处仅摘要。

| 档位 | 预算 | 核心能力 | 适用场景 | NexusSky 适配 |
|---|---|---|---|---|
| **toy**（百元级） | ~100 RMB | IMU 悬停 + WiFi 图传 + 超声波避障 | 室内编队演示、教育 | `--budget=toy`，禁 GPS / 雷达 / 热成像，通信降级 WiFi Mesh |
| **standard**（千元级） | ~1000 RMB | GPS 航点 + LoRa Mesh + MAVLink 接入 | 户外多机协同、巡检 | `--budget=standard`，启用 GPS / ToF / LoRa Mesh |
| **advanced**（进阶版） | ~2000 RMB | 千元级 + 光流 + 红外阵列 + 双频 GPS | 精准农业、应急侦察 | `--budget=advanced`，启用光流 / 红外阵列 / 双频 GPS |

- **实现状态**：`SimConfig.budgetMode` 三档解析已实现，传感器降级架构
  （`SensorHub` / `CommHub`）已落地；丐版 MAVLink 消息子集已定义。
- **边界**：BOM 与单价基于 2026-09 公开电商报价，实际采购需按批次核价；
  丐版方案未在真实硬件上跑通完整任务流，仅软件层验证。

### 2.9 已实现但未列入"对外主打"的能力

以下能力已实现（见 README.md），但**不作为中间件对外主打卖点**，避免与
客户上层业务冲突：

- M1 编队表演、M2 喷洒物流、M3 成像增强、M4 硬件抽象（雷达 / 旋翼 / LiDAR / IMU）：
  作为**可选模块**提供，客户按需启用。
- 物理引擎 v2、Failsafe、相机协议 v2：属于模拟器与协议栈能力，对中间件
  定位是**研发辅助**而非对外卖点。

## 3. 目标客户分析

### 3.1 二线整机厂商

| 维度 | 内容 |
|---|---|
| **画像** | 有飞控与整机制造能力，但无云端协同调度研发团队，年营收 1–10 亿。 |
| **需求** | 让自家整机开箱即有云调度 / 多机协同 / 应急指挥能力，无需自建后端团队。 |
| **痛点** | 自研云平台周期 1–2 年、人力 10+ 人起；大疆 Cloud API 不兼容自家飞控；PX4 SDK 是单机开发包非云平台。 |
| **付费意愿** | 中高。云能力是整机投标差异化项，可接受中间件授权 + 定制集成。 |
| **切入模块** | 全模块私有部署 + MAVLink 对接 + GCS OEM 贴牌。 |
| **预估客单价** | 50–200 万 / 项目（含定制集成）。 |

### 3.2 行业解决方案商（应急救援 / 安防 / 巡检 / 农业）

| 维度 | 内容 |
|---|---|
| **画像** | 深耕行业场景，有客户资源与行业 SOP，但缺底层平台与多机协同能力。 |
| **需求** | 应急指挥闭环、安防联动、多机协同调度、覆盖规划，且要求兼容已部署的安防硬件。 |
| **痛点** | 通用无人机平台不懂应急 SOP；自研应急编排周期长、试错成本高；安防硬件多厂商混部难统一接入。 |
| **付费意愿** | 高。项目制采购，预算来自行业客户（应急局 / 安防甲方 / 农业大户），价格敏感度低于自研成本。 |
| **切入模块** | 4a 空地一体化应急指挥 + M9 应急编排 + M5 mesh 自愈 + ONVIF 安防接入。 |
| **预估客单价** | 100–500 万 / 项目（含行业定制）。 |

### 3.3 飞控厂商

| 维度 | 内容 |
|---|---|
| **画像** | 自研飞控（PX4 衍生或完全自研），飞控能力强但上层应用与云平台能力弱。 |
| **需求** | 补齐云平台、多机调度、应急组网能力，形成"飞控 + 云端"完整方案对外投标。 |
| **痛点** | 飞控团队不擅长后端 / 前端 / Web GIS；自建云平台分散飞控研发精力；缺应急指挥行业 know-how。 |
| **付费意愿** | 中。技术导向客户，对"中间件授权 + 联合品牌"接受度高，对纯 SaaS 接受度低。 |
| **切入模块** | 中间件授权 + MAVLink 对接 + 联合品牌 + 应急指挥模块（4a + M9）。 |
| **预估客单价** | 80–300 万 / 年（授权 + 运维）。 |

### 3.4 eVTOL 企业

| 维度 | 内容 |
|---|---|
| **画像** | 研发载人或载货 eVTOL，适航与运营期多机调度是刚需，融资阶段或适航申报阶段。 |
| **需求** | 多机运营调度、低空通信组网、数字孪生用于适航验证、星地中继调度。 |
| **痛点** | 适航验证需要大量仿真数据，自建数字孪生成本高；运营期多机调度平台缺失；低空通信依赖运营商但覆盖不全。 |
| **付费意愿** | 中高。适航与运营均为强需求，但 eVTOL 企业研发能力强，可能自研部分模块，需找差异化切入点。 |
| **切入模块** | M7 星地中继 + M6 移动基站 + M9 应急编排 + 数字孪生（PoC 阶段为模拟器）。 |
| **预估客单价** | 100–300 万 / 项目（适航验证工具 / 运营调度平台）。 |

### 3.5 客户优先级

| 优先级 | 客户类型 | 理由 |
|---|---|---|
| ⭐⭐⭐ | 行业解决方案商 | 付费意愿最高、场景最匹配、应急救援行业经验可直接复用 |
| ⭐⭐⭐ | 飞控厂商 | 中间件定位最契合、 MAVLink 中立协议是天然抓手 |
| ⭐⭐ | 二线整机厂商 | 需求明确但决策链长、需整机集成验证 |
| ⭐⭐ | eVTOL 企业 | 预算充足但可能自研、需差异化切入 |

## 4. 竞品分析

> 任务指定对标：大疆 FlightHub 2 / 纵横 CW 飞行平台 / 极飞农业云。
> 通用 SDK 级竞品（PX4 SDK / ArduPilot MAVProxy / AirSim）见
> [`docs/competitive-analysis.md`](competitive-analysis.md)，此处不重复。

### 4.1 大疆 FlightHub 2

| 维度 | 大疆 FlightHub 2 | NexusSky |
|---|---|---|
| 定位 | 大疆设备云端管理 + 机场自动化 | 多厂商兼容的多机协同调度中间件 |
| 设备兼容 | 仅大疆设备 | MAVLink 中立协议，兼容 PX4 / ArduPilot / 自研飞控 |
| 多机协同 | 单机任务队列，无协同调度 | M9 应急编排 + 四级抢占式调度 + 覆盖优化 |
| 应急组网 | 无 | M5 AODV-lite mesh 自愈 + M7 星空地多层级中继 |
| 安防联动 | 无 | 4a ONVIF 接入（海康 / 大华 / 宇视）+ 报警联动 |
| 应急指挥闭环 | 无 | 4a 六阶段工作流（接报→研判→部署→执行→评估→总结） |
| 丐版硬件 | 需大疆整机，万元起 | toy / standard / advanced 三档，百元起 |
| 部署 | 公有云为主 | 私有化为主，模块化单体可裁剪 |
| 生态 | 大疆设备全覆盖，文档完善 | PoC 阶段，生态待建 |

**NexusSky 差异化**：多厂商兼容 + 应急指挥闭环 + 丐版硬件下限。
**NexusSky 劣势**：生态、文档、商用案例、真机验证均不如大疆。

### 4.2 纵横 CW 飞行平台

| 维度 | 纵横 CW 飞行平台 | NexusSky |
|---|---|---|
| 定位 | 纵横自家工业级无人机飞行管理平台 | 中立中间件，不绑整机 |
| 设备兼容 | 纵横整机为主 | MAVLink 中立，可对接纵横飞控（若开放 MAVLink） |
| 多机协同 | 单机任务管理为主，多机为队列 | M9 编排 + M5 mesh + 覆盖优化 |
| 应急组网 | 无 | M5 + M7 |
| 行业场景 | 测绘 / 巡检为主 | 应急救援 / 安防 / 巡检 / 农业（模块化） |
| 整机能力 | 纵横 CW 系列工业级整机 | 无整机，纯中间件 |
| 客户基础 | 已上市，有行业客户 | PoC 阶段 |

**NexusSky 差异化**：不与整机厂商竞争、应急指挥闭环、多层级中继。

## 6. 技术差异化

### 6.1 多厂商协议兼容（MAVLink 中立）

- **事实**：`mavlink-core` 模块纯 Java 17 实现 MAVLink v1/v2 协议栈，
  185 个单测，CRC 与官方 c_library_v2 逐字节一致；已消化 PX4 真固件
  协议差异（MISSION_REQUEST 拉取、MISSION_COUNT 拒绝 broadcast、
  MISSION_START 回退、nav_state 映射）。
- **差异化**：大疆 Cloud API 仅兼容大疆设备；纵横 CW / 极飞均绑自家整机。
  NexusSky 是**协议中立中间件**，客户自带任何 MAVLink 飞控即可接入。
- **边界**：当前仅在 PX4 / ArduPilot 协议语义上验证；自研飞控需客户
  提供 MAVLink 兼容层或付费定制对接。

### 6.2 应急指挥闭环（4a + M9 + M5）

- **事实**：4a 已实现 ONVIF 安防接入（海康 / 大华 / 宇视）+ 报警联动
  编排 + 六阶段应急指挥工作流；M9 已实现五阶段应急编排（灾区测绘 →
  覆盖规划 → 组网部署 → 持续服务 → 自愈重构）+ 四级抢占式调度；
  M5 已实现 AODV-lite mesh 自愈组网。
- **差异化**：大疆 FlightHub 2 / 纵横 CW / 极飞农业云**均无应急指挥
  闭环能力**。NexusSky 是该象限唯一具备"安防报警 → 自动调度无人机 →
  mesh 自愈组网 → 应急编排"全链路的产品。
- **边界**：应急 SOP 与真实应急指挥流程未对齐验证；ONVIF 三大厂商设备
  未做现场联调。

### 6.3 丐版硬件方案（百元 / 千元 / 进阶三档）

- **事实**：`docs/budget-hardware-design.md` 给出三档 BOM 与单价，
  `SimConfig.budgetMode` 三档解析已实现，传感器降级架构已落地。
- **差异化**：所有竞品均要求自家整机（大疆 / 纵横 / 极飞）或万元级
  通用硬件（PX4 整机）。NexusSky **百元级方案**让客户用 ESP32 + 玩具架
  跑通多机协同概念验证，是唯一具备"低成本概念验证路径"的产品。
- **边界**：丐版方案未在真实硬件上跑通完整任务流，仅软件层验证；
  BOM 单价基于公开电商报价，批次采购需核价。

### 6.4 多层级通信中继（M6 + M7）

- **事实**：M6 移动基站载荷（LTE / WiFi / LoRa）+ M7 星空地多层级中继
  （LEO 卫星 + HAPS + Mesh）已实现；link-sim 在 Starlink 画像
  （9.6% 丢包、25s 通 / 2.5s 黑洞）下完整任务流 PASS。
- **差异化**：竞品均无多层级中继能力。NexusSky 是唯一具备"卫星过境
  窗口预测 + 层级路由决策 + 链路切换"模型的产品。
- **边界**：未对接真实卫星过境数据源；基站载荷为软件模型。

### 6.5 开源 / 私有化部署

- **事实**：模块化单体架构，`docker-compose.yml` 一键编排，模块可裁剪。
- **差异化**：大疆 Cloud API 公有云为主、数据出客户域；NexusSky 私有化
  部署、数据不出客户域，满足应急 / 安防 / 军警数据敏感要求。
- **边界**：当前无鉴权、无持久化（内存态）、无多租户——商用落地必补
  （详见 §7）。

### 6.6 差异化总结

| 差异点 | NexusSky | 大疆 FlightHub 2 | 纵横 CW | 极飞农业云 |
|---|---|---|---|---|
| 多厂商协议兼容 | ✅ | ❌ 大疆封闭 | ❌ 纵横封闭 | ❌ 极飞封闭 |
| 应急指挥闭环 | ✅ | ❌ | ❌ | ❌ |
| mesh 自愈组网 | ✅ | ❌ | ❌ | ❌ |
| 多层级中继 | ✅ | ❌ | ❌ | ❌ |
| 丐版硬件 | ✅ 百元起 | ❌ 万元起 | ❌ 万元起 | ❌ 万元起 |
| 私有化部署 | ✅ | ❌ 公有云为主 | 部分 | ❌ SaaS 为主 |
| 农业垂直深度 | ❌ | ❌ | ❌ | ✅ |
| 整机生态 | ❌ | ✅ | ✅ | ✅ |

**NexusSky 不与整机厂商在"整机 + 飞控"层竞争，而在"中间件 + 应急闭环"

## 7. 边界与商用落地差距（诚实声明）

> 本节列出 PoC 阶段的已知边界，作为商用落地必须补齐的清单。

### 7.1 已知边界（来自 README.md "已知边界"章节）

- **无鉴权**：REST / WebSocket 无身份认证、无权限控制。
- **无持久化**：机队注册表、任务、路由表均为内存态，重启即丢
  （飞行日志已落盘 JSONL，例外）。
- **无真机气动模型**：`drone-sim` 为匀速直线 + 运动学 v2，非真实气动。
- **单机骨架路由**：命令通道走 UDP lastPeer 学习，多机改造点已标注。
- **MAVLink 签名未实现**：局域网内明文通信。
- **检测器是投影可见性**：无真实 CV 模型，接入点在 `CaptureService` 第 2 步。
- **前端本地仅静态检查**：`vite build` 在 CI 跑，本地沙箱受限。

### 7.2 商用落地必补项

| 项 | 优先级 | 工作量估算 | 备注 |
|---|---|---|---|
| 鉴权（OAuth2 / API Key） | P0 | 2–4 人周 | 多租户前置条件 |
| 持久化（Postgres + Redis） | P0 | 3–5 人周 | 替换内存态 |
| 真机集成验证（PX4 + ArduPilot） | P0 | 4–8 人周 | 含 SITL + 真机 |
| 多租户与计费 | P1 | 3–5 人周 | SaaS 模式前置条件 |
| MAVLink 签名 | P1 | 2 人周 | 安全合规 |
| ONVIF 三大厂商现场联调 | P1 | 2–4 人周 | 应急版核心卖点 |
| 应急 SOP 对齐 | P1 | 业务专家参与 | 非纯技术工作 |
| K8s 部署 + Helm chart | P2 | 2 人周 | 大客户运维要求 |

### 7.3 不夸大承诺

- 本白皮书所列能力**均已实现并通过 e2e 回归**（详见 README.md 与各
  `scripts/e2e-*.ps1`），但**仅在模拟器与 link-sim 损伤链路下验证**。
- 真机集群验证、真机气动、真机多机协同调度**尚未完成**，是商用落地
  的 P0 项。
- 丐版硬件 BOM 单价基于公开报价，**未包含批次采购议价、关税、物流成本**。
- 应急指挥工作流**未与真实应急指挥 SOP 对齐**，需行业客户参与调优。
